## V4 browser-based personal AI configuration (retained history)

V4 removes the need for ordinary users to edit `.env`: the local launcher opens the first setup page with a short-lived setup code. Users enter Base URL, model, provider Key and a separate service password, confirm the destination, and explicitly test before the server saves the configuration. Later launches retain that private server configuration. Settings changes validate the current password without requiring the old provider or session to remain usable; changing endpoints requires a new Key. The Key is temporarily present in the page while entered and submitted, but is not persisted in browser storage, URLs, records or exports, and saved Keys are not returned to the UI.

## Production gates

The V1/V2 browser suites ran the **local demo**. V3 additionally verifies the personal self-hosted UI with simulated responses and the real local HTTP routes against a fake provider; V4 adds browser-based configuration and private-server persistence checks, including password-authorized repair when the previous provider and session are unavailable. None of these verifies a real external provider, multi-user hosted PostgreSQL/RLS, two-device production claims, hosted object permissions, live audio grading, provider-side billing/quotas, backup deletion or a publicly deployed site. Refer to `RELEASE_GATES.md` and the backend's actual test report for those boundaries. A provider mock or local SQL execution must not be represented as a successful live Supabase/provider test.

Writing self-review and speaking preparation alternatives deliberately confirm an activity, not language competence. V3 can request actual model feedback about the provided writing sample, but this does not replace the separately labeled demo questions, grant scores or modify XP. Personal self-hosted nutrition can offer general meal guidance for consenting adults and model food estimates that require review; exact personal nutrition targets remain unavailable until an appropriate policy and real data providers are approved and configured. GitHub Pages cannot run the private Node.js routes, and multi-instance/serverless hosting is outside the current persistent-file limit design.
